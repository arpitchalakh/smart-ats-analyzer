# Smart ATS Web MVP

This folder is the SaaS-style MVP for Smart ATS Analyzer. It intentionally lives beside the original Streamlit prototype so the old implementation remains available while the product UI is tested.

## What is implemented

- Public landing page based on the purple/white Smart ATS concept
- Dashboard / resume analysis flow
- PDF and DOCX upload
- Fixed OpenAI model controlled by the server (users cannot choose the model)
- OpenAI Responses API + strict JSON Schema output
- 10-credit demo wallet
- 1 credit consumed only after a successful analysis
- zero-credit blocking + recharge message
- My Analyses history and report reopening
- My Profile demo view
- Billing & Credits demo view
- Help & Support view
- API key remains server-side

## Test-mode architecture

The current credit wallet and analysis history use browser `localStorage`. This is intentional for rapid MVP testing without login/database setup.

Do **not** treat browser credits as secure for a paid production release. A user can clear or modify local storage. Production credits must live in a server-side database and be changed transactionally.

## Run locally

```bash
cd web
npm install
cp .env.local.example .env.local
```

Set your API key:

```env
OPENAI_API_KEY=your_real_key_here
OPENAI_MODEL=gpt-5.6-luna
```

Then:

```bash
npm run dev
```

Open `http://localhost:3000`.

## Recommended deployment

For the web MVP, Vercel is the simplest Next.js deployment path:

1. Import the GitHub repository in Vercel.
2. Set **Root Directory** to `web`.
3. Add `OPENAI_API_KEY` and `OPENAI_MODEL` as environment variables.
4. Deploy.

Do not commit `.env.local`.

## Production phase after MVP validation

### Authentication

Use Supabase Auth with Google OAuth. The demo profile should then be replaced with the authenticated Supabase user.

Suggested tables:

```text
profiles
- id (uuid, FK auth.users)
- full_name
- avatar_url
- created_at

credit_wallets
- user_id
- balance
- lifetime_purchased
- lifetime_used
- updated_at

credit_ledger
- id
- user_id
- delta
- reason
- payment_id nullable
- analysis_id nullable
- created_at

analyses
- id
- user_id
- job_title
- company
- score
- result_json
- created_at

payments
- id
- user_id
- provider
- provider_order_id
- provider_payment_id
- amount_paise
- credits
- status
- created_at
```

Use Row Level Security so users can only access their own analyses and account data.

### Credit safety

In production, credit consumption should be atomic:

1. Authenticate user.
2. Verify wallet balance server-side.
3. Reserve/decrement one credit transactionally.
4. Run analysis.
5. If the analysis fails, refund the reserved credit in the same ledger model.

Never trust a browser-supplied credit balance.

### Payments

Razorpay can be added after people validate willingness to pay. Recommended flow:

1. User selects 10 credits for ₹99.
2. Server creates Razorpay order.
3. Browser completes Checkout.
4. Server verifies the signature.
5. Razorpay webhook is also verified server-side.
6. Only then add credits to the wallet ledger.

Do not credit accounts based only on a client-side success callback.

### Google login

The UI is already structured for a logged-in shell, but login is skipped during MVP testing. In the production phase add:

- Google OAuth button
- Supabase callback route
- protected dashboard routes
- server-side session checks
- sign out
- per-user profile/history/credits

## Social proof

The design concept included claims such as `1,000+ applicants` and `50+ HR professionals`. Keep these values configurable and do not publish them as factual social proof until they are genuinely supported.

For launch, safer early-stage language is:

- Built for job-specific resume matching
- Early access / beta
- AI-assisted resume-to-JD analysis
- Privacy-first server-side API processing

When real usage crosses a threshold, derive the displayed metric from actual database counts.

## Important product disclaimer

Smart ATS provides an AI-assisted estimate of resume/job-description alignment. It is not a score generated by Naukri, Workday, Greenhouse, Lever, Taleo, or another ATS vendor, and it cannot guarantee interview selection.
